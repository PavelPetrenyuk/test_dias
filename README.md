# Генератор артикулов по маскам

Этот проект нужен для того, чтобы из масок получить все возможные варианты
артикулов.

Например, если пришла маска `AB**`, то каждая `*` заменяется на один символ
из набора `0-9` и `A-Z`. В результате будут сформированы варианты `AB00`,
`AB01`, `AB0A` и так далее.

Проект не проверяет, существует ли такой артикул у производителя. Здесь мы
только генерируем все варианты, которые подходят под заданные маски. Проверка
артикулов должна выполняться дальше, в другой части системы.

## Что приходит на вход

На вход подаётся CSV-файл в кодировке UTF-8. Разделитель колонок — точка с
запятой.

Пример:

```csv
manufacturer;part_group;masks
ANYCOMPANY;Тросы стояночного тормоза;"AB**, AB-*, C*-B, 4VB****, 9JB****"
SOMECOMPANY;Фильтры;"FL*, FL-**, OF*-****"
Ford Motor Company;Рычаги подвески;"TR7**-**, TJ92***, 992J*****"
```

В одной ячейке может находиться несколько масок. Их можно разделять запятыми
или переносами строк.

Правила масок простые:

- `*` — один символ из `0-9` или `A-Z`;
- буквы, цифры и дефисы остаются без изменений;
- строчные буквы переводятся в верхний регистр;
- одинаковые маски внутри одной группы повторно не обрабатываются;
- если две маски могут создать одинаковые артикулы, файл будет отклонён.

Последнее правило нужно для того, чтобы в результате не было дубликатов.

## Как установить проект

Нужен Python версии 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install '.[dev]'
```

## Запуск через CLI

Сначала лучше проверить файл и понять, сколько артикулов будет создано:

```bash
article-masks plan examples/input.csv
```

На этом этапе файлы с артикулами ещё не создаются. Команда только проверяет
маски и считает примерный объём результата.

Для запуска генерации:

```bash
article-masks generate examples/input.csv --output result
```

Основные настройки:

```text
--shard-size 5000000
--compression gzip|none
--max-mask-combinations 100000000
--max-combinations 500000000
--buffer-records 10000
```

- `shard-size` — сколько артикулов записывать в один файл;
- `compression` — сжимать файлы через gzip или оставить обычный текст;
- `max-mask-combinations` — ограничение для одной маски;
- `max-combinations` — общее ограничение на один входной CSV;
- `buffer-records` — размер внутреннего буфера записи.

Большие числа можно писать с нижним подчёркиванием прямо в Python-коде,
например `5_000_000`. Это всё то же число `5000000`, просто так его проще
читать.

## Что будет в результате

Результат будет разбит на несколько файлов, чтобы не держать миллионы
артикулов в оперативной памяти и не создавать один огромный файл.

```text
result/
├── manifest.json
├── masks.csv
├── errors.csv
└── articles/
    └── group-0001/
        ├── mask-0001/
        │   └── part-00001.txt.gz
        └── mask-0002/
            └── part-00001.txt.gz
```

В каждом файле находится по одному артикулу на строку.

В `manifest.json` хранится описание результата: производитель, группа,
исходная маска, количество артикулов, список частей и SHA-256 каждой части.
Хеш нужен для проверки, что файл скачался полностью и не был повреждён.

## Запуск как веб-сервис

Веб-сервис работает по следующей схеме:

```text
CSV → API → очередь в PostgreSQL → worker → файлы результата
```

API принимает CSV и сразу возвращает идентификатор задания. Саму генерацию
выполняет отдельный worker, поэтому HTTP-запрос не висит всё время обработки.

Для запуска нужно создать файл с настройками:

```bash
cp .env.example .env
```

В `.env` обязательно нужно заменить значения `POSTGRES_PASSWORD` и
`API_TOKEN`.

После этого можно запустить весь сервис:

```bash
docker compose up --build
```

Будет запущено три контейнера:

- `api` — принимает запросы;
- `worker` — генерирует артикулы;
- `database` — хранит задания и их состояния.

API и worker используют общий Docker volume. Поэтому worker может записать
результат, а API — отдать его клиенту.

Проверить, что сервис запустился:

```bash
curl http://localhost:8000/health
```

## Как отправить CSV

```bash
curl -X POST http://localhost:8000/v1/jobs \
  -H "Authorization: Bearer $API_TOKEN" \
  -F "file=@examples/input.csv;type=text/csv" \
  -F "shard_size=5000000" \
  -F "compression=gzip"
```

В ответ придёт примерно такой JSON:

```json
{
  "id": "6dc3490d-28db-46f0-a651-0f250fb13d75",
  "status": "queued",
  "generated_articles": null,
  "error_message": null,
  "created_at": "2026-10-20T10:00:00Z",
  "started_at": null,
  "finished_at": null,
  "status_url": "http://localhost:8000/v1/jobs/6dc3490d-28db-46f0-a651-0f250fb13d75",
  "manifest_url": null
}
```

## Как проверить состояние задания

Нужно периодически вызывать `status_url`, например раз в несколько секунд:

```bash
curl \
  -H "Authorization: Bearer $API_TOKEN" \
  http://localhost:8000/v1/jobs/6dc3490d-28db-46f0-a651-0f250fb13d75
```

У задания может быть одно из четырёх состояний:

- `queued` — ожидает обработки;
- `running` — worker уже начал генерацию;
- `completed` — файлы готовы;
- `failed` — во время обработки произошла ошибка.

Когда `status` станет равен `completed`, в поле `manifest_url` появится
ссылка:

```json
{
  "id": "6dc3490d-28db-46f0-a651-0f250fb13d75",
  "status": "completed",
  "generated_articles": 126020556,
  "error_message": null,
  "manifest_url": "http://localhost:8000/v1/jobs/6dc3490d-28db-46f0-a651-0f250fb13d75/manifest"
}
```

Это означает, что результат можно забирать.

## Как скачать результат

Сначала нужно получить манифест:

```bash
curl \
  -H "Authorization: Bearer $API_TOKEN" \
  http://localhost:8000/v1/jobs/6dc3490d-28db-46f0-a651-0f250fb13d75/manifest
```

В манифесте перечислены пути ко всем сформированным частям. Каждая часть
скачивается отдельно:

```bash
curl \
  -H "Authorization: Bearer $API_TOKEN" \
  -o part-00001.txt.gz \
  http://localhost:8000/v1/jobs/6dc3490d-28db-46f0-a651-0f250fb13d75/files/articles/group-0001/mask-0001/part-00001.txt.gz
```

Если задание ещё не завершено, ручки манифеста и файлов вернут ошибку
`409 Conflict`.

## Как остановить сервис

```bash
docker compose down
```

Эта команда остановит контейнеры, но не удалит базу и сформированные файлы из
Docker volumes.

## Что пока не сделано

Сейчас клиент узнаёт о завершении через периодический запрос статуса. Отправки
webhook после завершения пока нет.

Автоматическое удаление результатов тоже пока не реализовано. В дальнейшем
можно добавить подтверждение успешного скачивания и отдельный cleanup-worker,
который будет удалять старые файлы через заданное время.
